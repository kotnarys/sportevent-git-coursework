# Техническое задание: SportEvent

## 1. Основания и назначение

Учебный проект по дисциплине «Проектная деятельность в ИТ». Вариант Н — программа информационной поддержки спортивных соревнований. Назначение: уменьшить ручной труд по учёту мероприятий, регистраций и расчёту мест.

## 2. Участники предметной области

- Организатор — планирование и публикация турниров.
- Секретарь — регистрация участников.
- Судья — внесение и подтверждение результатов.
- Зритель/спортсмен — просмотр расписания и результатов.

Эти роли зафиксированы как **требование к полной системе**; в MVP разделение прав не реализовано.

## 3. Функциональные требования MVP

| ID | Требование | Критерий приемки |
|---|---|---|
| FR-01 | Просматривать список соревнований | Видны название, дата, место, дисциплина |
| FR-02 | Добавлять соревнование | Запись появляется в списке после валидации |
| FR-03 | Вести реестр спортсменов | Новый спортсмен виден в реестре; дубликаты отклонены |
| FR-04 | Регистрировать на соревнование | Повторная регистрация запрещена |
| FR-05 | Вносить результаты | Только для зарегистрированного спортсмена, положительное число |
| FR-06 | Автоматически вычислять место | asc для времени, desc для длины, равные места |
| FR-07 | Экспортировать протокол | Получается CSV с местом, участником, командой, результатом |
| FR-08 | Сохранять локальное состояние | Состояние восстанавливается при обновлении страницы |

## 4. Нефункциональные требования

- Интерфейс на русском языке, адаптация к настольному и мобильному экрану.
- Доступность без подключения к внешним API (внешний веб-шрифт необязателен).
- Отсутствие внешних пакетов для работы приложения.
- Покрытие предметных функций автоматическими тестами Node.js.

## 5. Модель данных

**Event**: `id`, `name`, `sport`, `date`, `place`.
**Athlete**: `id`, `name`, `team`.
**Registration**: `eventId`, `athleteId`.
**Result**: `eventId`, `athleteId`, `value`.

Связь `Event↔Athlete` — многие ко многим через `Registration`. Каждый зарегистрированный участник получает не более одного итогового результата в соревновании; повторный ввод обновляет его значение.

## 6. Ограничения и риски

- `localStorage` не обеспечивает синхронизацию, авторизацию, аудит действий и сохранность данных между устройствами.
- Отсутствует серверная проверка полномочий: сведения в MVP демонстрационные.
- В продуктивной версии потребуются БД, API, управление доступом, резервное копирование и протоколирование правок.
